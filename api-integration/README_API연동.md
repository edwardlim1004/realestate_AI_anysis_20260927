# 국토부 실거래가·전세가 API 연동 가이드

## 🔐 인증키 보관 원칙 (가장 중요)

이 저장소는 **Public**이므로, 인증키를 코드에 직접 적어서 커밋하면 전 세계에 노출됩니다.
그래서 모든 스크립트는 키를 **코드에 절대 적지 않고**, 아래 두 경로 중 하나에서만 읽습니다.

| 상황 | 키를 넣는 곳 | GitHub에 올라가는가? |
|---|---|---|
| 내 컴퓨터에서 직접 테스트 | `api-integration/.env` 파일 | ❌ 안 올라감 (`.gitignore`에 등록됨) |
| GitHub Actions 자동 실행 | 저장소 Settings → Secrets → `MOLIT_SERVICE_KEY` | ❌ 안 올라감 (Secrets는 암호화 저장, 로그에도 안 보임) |

**`.env` 파일이나 실제 키 값이 담긴 어떤 파일도 GitHub에 업로드하지 마세요.** (`.gitignore`가 자동으로 막아줍니다.)

## 파일 설명

| 파일 | 역할 |
|---|---|
| `regions_lawd.py` | 56개 지역 ↔ 법정동코드(LAWD_CD) 매핑 (매매/전세 공통) |
| `fetch_molit.py` | 아파트 **매매** 실거래 API 호출 → 지역별 월별 평균가(전체/전용84㎡) 수집 |
| `fetch_jeonse.py` | 아파트 **전월세(전세)** 실거래 API 호출 → 지역별 전세가율(%) 계산 |
| `merge_into_datajs.py` | 위 두 결과를 기존 `data.js`에 병합, 점수·신호 재계산 |
| `update-data.yml` | 매달 자동으로 위 세 스크립트를 실행하고 결과를 자동 커밋하는 GitHub Actions |
| `.env.example` | 로컬 테스트용 키 입력 템플릿 (실제 키는 여기 적지 말고 `.env`로 복사해서 사용) |
| `.gitignore` | `.env`(인증키 파일)가 실수로도 커밋되지 않도록 차단 |

## A. 로컬에서 한 번 테스트해보기

```bash
cd api-integration
pip install requests

cp .env.example .env
# .env 파일을 열어서 MOLIT_SERVICE_KEY=발급받은키 로 실제 키 입력

# fetch_molit.py 상단의 REGION_FILTER = ["강남구","서초구"] 로 우선 2개 지역만 테스트
python fetch_molit.py            # -> molit_fetched.json 생성 (매매 데이터)
python fetch_jeonse.py           # -> jeonse_fetched.json 생성 (전세가율)

cp ../data.js .                  # 기존 data.js 복사
python merge_into_datajs.py      # -> data.js 갱신 (전세가율 포함)
cp data.js ../data.js            # 원래 자리로 되돌리기
```

정상 동작하면 `REGION_FILTER = None` 으로 바꿔서 56개 전체 지역을 수집하세요.

## B. 완전 자동화 (GitHub Actions) — 추천

1. **공공데이터포털에서 두 API 모두 활용신청** 되어 있는지 확인
   - 국토교통부_아파트매매 실거래 상세 자료 (`RTMSDataSvcAptTradeDev`)
   - 국토교통부_아파트 전월세 실거래자료 (`RTMSDataSvcAptRent`) ← 전세가율용, 별도 승인 필요
2. 저장소 **Settings → Secrets and variables → Actions → New repository secret**
   - Name: `MOLIT_SERVICE_KEY`
   - Value: 발급받은 서비스키 (두 API 공통으로 같은 키 사용)
3. 아래 파일들을 저장소에 업로드
   - `api-integration/regions_lawd.py`
   - `api-integration/fetch_molit.py`
   - `api-integration/fetch_jeonse.py`
   - `api-integration/merge_into_datajs.py`
   - `api-integration/.gitignore` (이 폴더 안에 별도로 둬도 되고, 저장소 루트 `.gitignore`에 내용만 합쳐도 됨)
   - `.github/workflows/update-data.yml` ← 반드시 이 정확한 경로
   - **`.env`나 `.env.example`은 올릴 필요 없습니다** (Actions에서는 Secrets를 바로 씁니다)
4. 저장소 **Actions** 탭 → "Update Real Estate Data" → **Run workflow** 로 수동 실행해서
   `data.js`가 갱신·자동 커밋되는지 확인
5. 이후 매달 1일 자동 실행되어 매매 시세 + 전세가율이 함께 갱신됩니다.

## C. 전세/월세 "스프레드" 모델 — 학술적 배경과 적용 방식

### C-1. 왜 단순 전세가율(J/P)로는 부족한가

매매가 10억·전세 6억이면 전세가율은 항상 60%로 동일합니다. 하지만 전월세전환율이 연 3%일 때와
6%일 때, 그 전세금이 "실제로 창출하는 연간 임대가치"는 2배 차이가 납니다. 즉 **같은 갭이라도
금리·전환율 환경에 따라 실제 평가가 달라져야 한다**는 것이 핵심 문제의식입니다.

- **Himmelberg, Mayer & Sinai (2005, Journal of Economic Perspectives, 19(4), 67–92)**
  단순 가격/임대료 비율만으로는 주거비용을 제대로 평가할 수 없고, 금리(r)·세금(δ)·기대상승률(g)을
  반영한 "사용자비용(user cost)"으로 봐야 한다고 지적합니다. 이 프로젝트에서는 주담대 금리를
  `r`로 사용해 임대수익률과 비교하는 "스프레드" 방식으로 구현했습니다.
- **이현탁 (2019), "전월세전환율을 통한 주택시장 동적관계 연구", 『국토연구』 103, 41–60, 식 2**
  전세보증금(J)과 반전세 보증금(D)·월세(M)를 전월세전환율(k)로 연결합니다:
  `k = 12M / (J - D)`. 이를 이용해 전세금을 "연간 환산 임대료(R = k×J)"로 바꿀 수 있습니다.
- **Joshua Gallin (2008), "The Long-Run Relationship Between House Prices and Rents",
  Real Estate Economics, 36(4), 635–658**
  임대료-가격 비율의 괴리는 단기 노이즈가 아니라, 향후 수년간 실질 매매가 변화에 대한
  평균회귀적 예측력을 가진다는 실증 결과입니다. 스프레드를 "장기 평가지표"로 쓰는 근거입니다.
- **조태진 (2015), 『부동산학연구』 21(2), 57–69** — 중요한 경고: 전세가율(갭) 축소가 항상
  매매가 상승 신호는 아닙니다. 매매가 급락으로 갭이 줄어든 "침체성 축소"와, 전세 수요 증가로
  갭이 준 "건전한 축소"는 구분해야 합니다. 그래서 아래처럼 `gapPhase` 라벨을 별도로 둡니다.

### C-2. 실제 계산 흐름 (코드 위치)

| 단계 | 파일 | 내용 |
|---|---|---|
| 1. 전월세전환율(k) 추정 | `fetch_jeonse_incremental.py` → `estimate_conversion_rate()` | 같은 지역의 반전세/월세 거래에서 `k = 12M/(J-D)` 를 건별로 구해 **중앙값**을 사용 (이상치 제거: 연 1~15% 범위 밖 제외). 표본 5건 미만이면 기본값 `DEFAULT_K = 4.5%` 사용 |
| 2. 내재 임대수익률 | 동일 파일 | `연간환산임대료 = k × 전세보증금평균`, `임대수익률(%) = 연간환산임대료 / 매매가 × 100` |
| 3. 금리보정 스프레드 | 동일 파일 | `스프레드 = 임대수익률 - 주담대금리(4.39%)` → Himmelberg et al.(2005)의 사용자비용 비교 |
| 4. 종합점수 반영 | `merge_into_datajs.py` | 기존 "전세가율 백분위" 자리를 **"스프레드 백분위"**로 교체 (가중치 15%는 동일 유지) — 단순 전세가율과 정규화갭(1-J/P)은 같은 정보의 역수라 중복 반영을 피했습니다 |
| 5. 갭 변화 국면 | `merge_into_datajs.py` | 모멘텀(trendN)과 밸류에이션갭(gapPct)을 조합해 `거품성 갭 확대 우려` / `침체성 조정 중` / `건전한 회복` / `중립·혼조` 4단계로 분류 (조태진 2015의 경고 반영) |

### C-3. 데이터 수집 자체

- `fetch_jeonse_incremental.py`가 최근 6개월간 전용 80~90㎡ 거래를 받아, **순수 전세**(월세 0원)는
  평균 보증금 계산에, **반전세/월세**(월세 > 0원)는 전환율(k) 추정에 각각 사용합니다.
- 거래 표본이 부족한 지역은 전세가율은 기존 값을 유지하고(`건너뜀` 로그), 스프레드는
  `jeonseEstimated: true` 플래그와 함께 기본 전환율로 추정치를 산출합니다 — 화면에는 "(추정)"으로 표시됩니다.
- `merge_into_datajs.py`가 56개 지역 전체를 다시 백분위 점수로 환산해 `scores.jeonse`(이제는
  스프레드 기준)를 갱신하고, 종합점수·신호(🟢🟡🔴)가 자동으로 업데이트됩니다.

### C-4. 한계와 추가 검증이 필요한 부분 (솔직하게)

- k(전환율) 추정은 "같은 단지·같은 시점"의 짝지은(paired) 비교가 아니라 지역 평균 전세가를
  기준값(J)으로 삼는 **근사치**입니다. 더 정밀하게 하려면 단지 단위 매칭이 필요합니다.
- 스프레드가 장기적으로 평균회귀한다는 Gallin(2008)의 결과는 미국 자료 기준이며, 이 프로젝트의
  5년 수집 기간은 장기 사이클을 포함하지 못해 **예측력이 검증된 상태는 아닙니다**. 신호등은 참고용
  판단 보조 도구이며, 백테스트(기준모형 대비 6·12·24개월 예측오차 비교) 전까지는 확정적 매수/매도
  근거로 쓰면 안 됩니다.
- `gapPhase` 분류는 "건전/침체/거품" 국면 구분을 보여주는 **정성적 참고 라벨**이며, 가중 점수에는
  반영되지 않습니다(의도적으로 제외 — 단순화된 2변수 분류라 과신하지 않도록).
