# 서울·경기·대전 아파트 원본 수집과 증분 갱신

## 2026-10-27 누락 원인과 수정

실제 파일 30,062개는 SHA256·행 수·원본 JSON 검증에 모두 통과했습니다.
그러나 부천·화성·여주에 대해 행정구역 신설일 이전을 제외한 조회 계획이 잘못되어 있었습니다.
국토부 API는 **현재 지역코드로 과거 계약도 제공**합니다. 제외 기간 60구간을 실제 조회해
현재 8개 코드의 과거 자료 32구간이 제공되는 것을 확인했습니다.

현재 경기도 31개 시·군의 47개 코드 각각을 매매 2006-01부터, 전월세 2011-01부터
현재 계약월까지 조회합니다. 신설일 기준의 과거자료 차단을 제거했습니다.
2026-10 기준 경기도 목표는 매매 11,750 + 전월세 8,930 = **20,680구간**입니다.
검증 당시 17,752구간이 확보되어 있었고, 추가 조회가 필요한 구간은
부천 1,116 + 화성 1,688 + 여주 124 = **2,928구간**이었습니다.

옛 코드의 0건 원본 1,310개는 보존하되 활성 수집·진행률 분모에서 제외합니다.
진행률 기준이 바뀐 날은 전일 증감 계산에서 제외하여 수집량을 잘못 표시하지 않습니다.
구간은 지역코드×계약월×매매/전월세 조회 단위이며 거래 건수가 아닙니다.

## 주기와 저장

서울 25개 구, 경기도 현행 47개 코드, 대전 5개 구가 기존 3시간 간격 작업에 포함됩니다.
최근 6개월은 하루 한 번 재확인하고 원본 내용이 다른 구간만 저장합니다.
신규·정정·해제·제외에 대한 변화 요약은 `updates/YYYY/MM.jsonl`에 남깁니다.
6개월보다 오래된 계약의 늦은 정정은 별도 확장 갱신이 필요합니다.
같은 특성의 실제 거래가 여러 건이면 원본의 건수를 보존합니다.

전체 지역과 검증이 일일 8,000회 한도를 공유합니다. 수집 호출당 최대 1,200회,
요청 간 최소 3초를 유지합니다. 최초 적재는 200회 요청마다 진행을 커밋하며,
일일 예산이 소진되거나 API가 안전 중단되면 다음 정기 실행에서 이어갑니다.

R2는 계정 전체 측정과 공동 8GB 안전선을 통과할 때만 원본을 추가합니다.
측정 불가·안전선 초과 시 검증된 Google Drive 저장으로 전환합니다.
기존 원본 경로·백업 파일 식별자는 유지하고 지역별 폴더를 구분합니다.

- `backfill_progress.json`: 서울 목표 11,000구간.
- `gyeonggi_backfill_progress.json`: 경기도 목표 20,680구간.
- `daejeon_backfill_progress.json`: 대전 목표 2,200구간.
- `coverage_audit.json`: 서울·경기 현재 수집 대상의 실제 파일 및 원천 표본 검증.
- `region_history_audit.json`: 제외 코드 기간의 원천 제공 여부 확인.
- `daejeon_coverage_audit.json`: 대전 전체 저장 후 같은 방식의 검증.

검증 증거의 기존 객체와 SHA256·크기·저장소 식별자가 모두 같으면 전수 재독출 증거를
재사용하고, 추가·변경된 객체는 실제로 다시 읽습니다. 이후 현재 수집 대상 중 0건인 구간
전부와 지역·연도·유형별 표본을 API로 재조회합니다. 이 표본 확인은 모든 거래의
재수집을 뜻하지 않습니다. 복구 후 원본 파일은 서로 다른 시점에 검증되었음을 기록합니다.

```bash
python seoul-apartment-collector/collect.py --region gyeonggi --mode daily --max-requests 1200 --delay 3
python seoul-apartment-collector/backfill_progress.py --region gyeonggi
```

## 2026-10-21 실행 #15 기록 복구

원본 수집·R2 업로드는 성공했으나, 갱신된 초기 CSV가 작업 폴더에 남아 있어
`git pull --rebase`가 중단됐습니다. 동기화에 `--autostash`를 적용해 임시 CSV를
보관한 상태에서 기록을 올리고, 독립적인 다른 변경도 유지합니다.

`recover_failed_run.py`는 이 실행의 로그와 진단 파일로 만든 복구 계획을 사용합니다.
변경된 1,049개 R2 원본의 수정 시각·gzip·행 수·SHA256·전체 바이트 합계가 모두
일치해야 경기도 814구간과 당일 API 사용량 4,657회를 복구합니다. 국토부 API를
다시 호출하지 않으며, 완료 표식을 남겨 다음 실행에서는 건너뜁니다.

기존 진단 파일에 포함되지 않았던 구간별 변경 요약은 정확히 재구성할 수 없습니다.
기존 구간은 `recovered_snapshot`으로 표시하고 추가/제외 건수는 null로 남깁니다.
실행 전체의 추가·제외 건수는 복구 영수증에 보존합니다. 앞으로 실패하더라도
복구할 수 있도록 진단 파일에 매니페스트와 변경 요약도 함께 보관합니다.
