# 경기도 저장 진행률: 매일 오전 9시 카카오톡

`gyeonggi-daily-kakao.yml`과 `kakao_daily_progress.py`가 기존 카카오톡 **나와의 채팅**
연결을 사용합니다. 매매·전월세별 저장/목표 구간과 진행률, 합계, 전일 보고 대비 증감,
서울과의 대상 기간 및 관측일 일치 여부, 마지막 수집 실행의 오류 수를 보냅니다.
구간은 지역 코드 × 계약월 × 매매/전월세이며 거래 건수와 다릅니다.

## 예약과 중복 방지

- 한국시간 09:00, UTC 00:00 cron을 설정합니다. 실행 대기열 때문에 도착이 늦어질 수 있습니다.
- 수동 재실행도 동일한 보고 작업을 사용합니다. 이 작업은 `main`을 명시적으로
  체크아웃하므로 예전 작업을 재실행해도 최신 자료와 코드를 읽습니다.
- 모든 시작 경로가 같은 Actions concurrency 그룹을 사용합니다. 한국 날짜별 발송
  영수증을 기존 R2의 `internal/kakao-gyeonggi-progress/v1/YYYY-MM-DD.json`에 저장합니다.
  재실행 시 이미 성공한 날은 건너뜁니다. 9시 이전에는 메시지를 보내지 않습니다.
- 카카오 API가 성공을 반환한 뒤에만 `sent`와 응답 코드 0을 기록합니다. 네트워크 오류로
  결과가 불확실하면 예약 표식을 유지하고 자동 중복 발송을 차단합니다. 영수증과
  카카오톡 수신 여부를 확인한 후 해당 날짜만 수동으로 복구해야 합니다.
- 기존 암호화된 카카오 refresh token과 GitHub Secrets를 재사용합니다. 토큰은 기록하거나
  출력하지 않습니다. 보고 작업은 원본 API를 다시 호출하지 않으며 Git에 쓰지 않습니다.

## 서울과 같은 기간으로 비교

서울·경기도 모두 매매는 2006-01부터, 전월세는 2011-01부터 현재 계약월까지입니다.
행정구역 개편에 따른 과거 코드는 기존 `regions.py`의 계약월 범위를 따릅니다.
저장 진행률 목표는 월이 바뀌면 두 지역 모두 같은 새 계약월까지 늘어납니다.

동일 계약월이라도 조회일이 다르면 뒤늦게 신고되거나 정정된 내용 때문에 비교가 달라질
수 있습니다. 수집 성공 시, 변경이 없는 경우에도 각 구간에 `checked_at_utc`를 기록합니다.
과거 파일의 조회일을 매니페스트 전체 저장 시각으로 추정해서 채우지는 않습니다.

보고서는 당월을 잠정 자료로 보고, 전월 계약분에 대해 서울·경기도의 모든 지역과
매매·전월세 구간이 저장됐는지, 마지막 실제 확인일이 한국 날짜로 같은지 검사합니다.
누락·미기록·서로 다른 날짜는 비교 준비 완료로 처리하지 않습니다. 날짜가 같아도
공식 자료의 고정 빈티지가 보장되는 것은 아니며 추후 정정이 있을 수 있습니다.
기본 최근 6개월 정기 갱신이 진행되면서 확인일 정보가 채워집니다.

## 검증과 진단

```bash
python seoul-apartment-collector/test_kakao_daily_progress.py
python seoul-apartment-collector/kakao_daily_progress.py --dry-run
```

`daily_progress_report.json`은 실행 아티팩트로 30일간 보존합니다. 구간 수는 기존
업로드 확인 매니페스트의 SHA256/바이트/저장 방식 조건을 검증한 값입니다. 매일
모든 원본을 재다운로드하거나 개별 거래 내용의 전수 검증을 하는 것은 아닙니다.
