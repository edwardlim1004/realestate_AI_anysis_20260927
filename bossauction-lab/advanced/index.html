기존 경·공매 SQLite DB 연결

기존 v11.4의 DB를 온라인 브라우저에서 직접 읽습니다. 원본 DB를 GitHub에 올릴 필요가 없습니다.

① 기존 v11.4 SQLite 파일 연결

프로그램 ZIP을 압축 해제해 auction_v11.sqlite3를 선택하세요. WebAssembly 기반 SQLite 엔진이 파일을 이 브라우저 안에서 읽습니다.

연결 전 · DB 파일은 서버나 공개 GitHub 저장소에 업로드하지 않습니다.

선택 저장 시 원본 DB 전체가 아닌 검색용 물건 목록만 이 기기의 브라우저 저장공간(IndexedDB)에 남습니다. 공용 PC에서는 선택하지 마세요. SDK/SQLite 실행에 필요한 공개 라이브러리 파일은 CDN에서 다운로드됩니다.

원래 v11.4 DB에는 2026-10-17 기준 경매 21건이 보관되어 있고 좌표가 없으므로 목록·검색은 가능하지만 지도 마커는 나타나지 않습니다. 실제 기일은 법원 원문을 다시 확인해야 합니다.

② 네이버 주소→좌표 변환 및 지도 마커

기존 지도에 연결한 뒤 최대 5개 고유 지번씩 NAVER Geocoding API를 요청합니다. 같은 지번의 여러 물건은 한 번만 조회합니다. 호출마다 네이버 Maps 사용량·요금이 발생할 수 있습니다.

좌표 미확보 물건 0건

주소가 정확하게 일치하는 경우에만 지번 대표 좌표가 자동 반영됩니다. 부정확하거나 여러 후보인 경우 직접 선택해야 합니다.

주소 불일치·복수 후보 확인

API에 주소가 전달됩니다. 지번 대표점은 정확한 건물 출입구·토지 경계가 아니며 등기/공부 및 사건 현황과 대조해야 합니다. 위치를 적용하면 현재 목록 JSON 내보내기로 결과를 보관할 수 있습니다. 브라우저 자동 저장은 SQLite 연결 시 별도 선택한 경우만 작동합니다.

③ CSV / JSON 가져오기 (추가 선택)

브라우저 메모리에서 처리하고 서버로 전송하지 않습니다. 새로고침하면 데이터가 비워집니다.

온라인 DB / API 한계

GitHub Pages는 Python·SQLite 서버를 실행할 수 없지만, 선택한 SQLite DB 파일은 브라우저 안에서 직접 읽습니다. 새 물건을 자동 수집하거나 실시간 법원·온비드 DB를 갱신하지는 않습니다.

행에 위도/경도가 없는 물건은 좌표 미확보로 분류합니다. 주소만으로 가짜 마커를 만들지 않습니다.

v11.4 Python 백엔드의 온라인 자동 업데이트·DB 서버 기능은 별도 호스팅이 필요합니다. 현재는 사용자가 직접 선택한 DB 파일의 스냅샷만 읽습니다.
