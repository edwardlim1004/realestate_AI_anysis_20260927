# Auction Lab v11 Pages: 네이버 지도·경매/공매 워크스페이스

복구된 2026-10-18 BossAuction Reference v11.4의 자체 개발 기능을 참고해 다시 작성한 정적 웹용 버전입니다.
로컬 Python/SQLite 전체를 서버처럼 실행하는 배포가 아닙니다. 원본 대장옥션의 공식 서비스·비공개 API·저작물과 무관합니다.

## 온라인에서 가능한 기능
- 경매·공매 통합 필터, 물건 상세, 일정, 관심물건, 최대 3건 비교
- CSV/JSON 수동 가져오기(8MB, 1~10,000건), 브라우저 내 검색·정렬·지도 영역 필터
- 네이버 Web Dynamic Map v3 사용자 명시 실행, 실제 지도 이동·줌, 위성/지적도, 좌표가 있는 마커와 상세정보
- 지도 클릭을 통한 폴리라인 거리 및 다각형 면적 계산. 필지 법적 면적 아님
- 좌표 미제공 물건 지도 미표시, 사용자가 선택한 시험 좌표는 출처를 별도로 기록
- 권리문서 점검표(법률판정 아님), 낙찰 비용 산술 계산
- 기본 데이터 0건. 가상 데이터는 사용자가 예제 버튼을 누를 때만 표시

## 네이버 지도 활성화
1. 네이버 클라우드 새 Maps 상품에서 Web Dynamic Map 신청.
2. 허용 서비스 URL에 https://edwardlim1004.github.io 등록.
3. 지도검색의 연결 설정에서 새 ncpKeyId (Client ID)만 입력. Client Secret 입력 금지.
4. 실제 타일과 인증은 해당 개발자 계정 및 웹 브라우저 환경에서 확인.
5. 2026-06-25 AI NAVER API 지도 상품은 종료됐으므로 기존 Client ID가 동작하지 않을 수 있음.

## 네이버 Geocoding으로 기존 DB 위치 표시 (2026-10-25 적용)

1. 기존 DB(`auction_v11.sqlite3`) 연결, 네이버 지도 SDK 실행.
2. 지도에서 **주소→좌표 5곳 조회** 또는 데이터 연동에서 **현재 미검색 지번 최대 5곳 조회**를 명시적으로 클릭.
3. `naver.maps.Service.geocode({query})`를 사용해 지번주소를 조회. **SDK Geocoder 서브모듈과 Geocoding 상품이 필요**합니다. 브라우저에 Client Secret 저장 없음.
4. 같은 지번의 다수 물건은 주소당 API 1회. 응답의 지번이 쿼리와 정확히 일치하는 경우에만 자동 적용하고, 불명확한 결과는 **수동 확인**에 표시. 좌표 실패/없는 주소는 지도 마커 없음.
5. 매 회 클릭 시 **고유 주소 최대 5건을 순차 요청**하고 성공한 지번의 대표 좌표를 마커로 표시하며 해당 지역으로 지도를 이동. 잔여 지번은 다음 버튼 클릭 시 조회.
6. **비용 주의:** Geocoding 사용량·요금이 발생할 수 있습니다. 이용량은 네이버 콘솔에서 확인. 반복 조회는 기본적으로 하지 않으며 재검색은 별도 버튼으로 수행.
7. 조회한 좌표는 사용자 브라우저 현재 목록에 반영. 기존 DB 연결 단계에서 브라우저 보관을 선택한 경우에만 IndexedDB에 갱신해 다음 방문에 보존. 그 외에는 **현재 목록 JSON 내보내기**로 로컬에 보관 가능.
8. 네이버 지도 SDK 동작은 브라우저 사용자 계정에서 확인해야 하며, 2026-10-17 기준 DB는 최신 사건 상태를 보장하지 않습니다.

공식 문서: https://navermaps.github.io/maps.js.ncp/docs/tutorial-Geocoder-Geocoding.html

## 기존 SQLite DB 직접 연결 (2026-10-24 적용)

1. 이전 프로그램 ZIP `BossAuction_Reference_v11_4.zip` 전체를 압축 해제해 `auction_v11.sqlite3` 파일을 찾습니다.
2. GitHub Pages에서 **데이터 연동 → 기존 v11.4 SQLite 파일 연결**을 선택합니다.
3. 파일을 선택하고 **기존 SQLite DB 연결 및 물건 검색**을 누르면 브라우저 안에서 DB 스키마를 검사하고 `items` 테이블을 읽습니다. 파일은 서버에 전송되지 않습니다.
4. 최초 복구본은 **2026-10-17 기준 경매 21건, 실좌표 0건**입니다. 검색·상세·일정에는 표시되지만 지도 마커는 없습니다. 온라인 최신 여부 보장하지 않습니다.
5. ‘이 브라우저에 저장’을 선택하면 정규화된 검색 목록만 IndexedDB에 저장되어 다음 방문에 자동 복원됩니다. 선택하지 않으면 현재 탭에서만 사용합니다.
6. **저장본 삭제·연결 해제**로 IndexedDB 자료를 삭제합니다. 공용 기기에서는 로컬 저장하지 마세요.

브라우저용 SQLite 엔진 `sql.js 1.13.0`(MIT)을 버전 고정된 CDN에서 받습니다. DB 파일 자체는 Github Pages나 CDN 서버로 전송하지 않습니다.
이는 **온라인에서 로컬 DB 스냅샷을 조회하는 기능**으로, 서버에 보관된 SQLite를 여러 사용자가 공동 조회하거나 공식 원천이 자동 갱신되는 시스템은 아닙니다.

## 기존 v11.4 DB 연동 (JSON 변환 대안)
기존 DB 파일을 브라우저에서 직접 연결하는 기능이 우선 지원됩니다. SQLite 엔진 사용이 불가능한 경우에 한해 로컬에서 tools/export_v11_sqlite.py를 실행한 뒤 출력 JSON을 브라우저에 불러올 수도 있습니다.
명령: python tools/export_v11_sqlite.py path/to/auction_v11.sqlite3 v11-export.json
사용권이 없는 원본 저장 화면과 이미지, API 비밀키, 개인정보 DB는 공개 저장소에 업로드하지 마세요.

지원 JSON: 최상위 sourceName, collectedAt 및 lots 배열. CSV: id, channel, title, region, type, location, authority, appraisal, minimum, date, failures, area, lat, lng, coordinateSource, sourceUrl 및 대응하는 대표적인 한글 헤더.
channel 값은 court/public 또는 경매/공매. 금액은 원, 기일은 YYYY-MM-DD.

## 아직 연동되지 않은 것
- 전국 법원·온비드 공식 실시간 API(공식 권한 및 서비스키/별도 서버 필요)
- Python 백엔드/SQLite **서버** 실시간 질의, 아파트 실거래 대용량 자동 수집(로컬 v11.4 기능에 남음); 파일 기반 SQLite 읽기는 브라우저에서 지원
- 실제 물건 위치 자동 지오코딩, 정식 로그인/결제/AI 권리 안전성 판정
- 지도 이동 시 원격 서버 호출 대신 현재 브라우저에 가져온 데이터에 한해 필터링

확인: Node.js에서 npm test 및 GitHub Actions. 실제 Maps 계정 인증·지도 타일 출력은 클라이언트 환경에서 별도 검증해야 합니다.
